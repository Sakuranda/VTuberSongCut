# 技术调研与证据边界

核对日期：2026-10-15。目标是为“拾歌 · VTuber SongCut —— VTuber直播自动歌切工具”选择可替换组件。下述官方资料说明候选技术的用途；不代表本项目已经接入或完成真实录播验收。

## 1. 唱歌区间检测：优先复用 AutoSlicer-v2

[AutoSlicer-v2 上游](https://github.com/anAtheist987/AutoSlicer-v2)面向指定主播的唱歌检测，包含特征提取、CRNN、训练、推理与区间后处理。预训练适用对象是阿梓；另一个主播的歌回应重新评估或训练，不能默认泛化。[上游实验报告](https://github.com/anAtheist987/AutoSlicer-v2/blob/master/reports/FINAL_REPORT.md)可用于了解其评估设计。

上游 README 报告独立测试事件级 F1 0.90、2.5 小时录播约 15 秒处理等结果。这些是**上游在其数据、硬件与流程上的报告**，不是本项目在 Mac 上的测量。下载、解码、特征、推理、渲染的耗时必须分开记录；加字幕重编码也不能沿用流复制切片的速度结论。[来源：上游 README](https://github.com/anAtheist987/AutoSlicer-v2#readme)。

本项目将上游放在独立 Git 仓库，Apple Silicon 修改单独留补丁，避免把 Web 产品逻辑塞入训练代码。合成输入上的 train/infer/eval/cache 测试只证明执行链与设备兼容性，不证明阿梓真录播上的准确率。发布质量结论前需要人工标注、按录播隔离的数据划分、固定模型/阈值和误差分析。

需要核实代码、预训练权重、训练素材和再分发条件。上游代码所附许可证不能自动代表权重或直播内容许可。RVC 等音色转换技术解决的是声音转换，不作为唱歌区间检测器或主播身份检测器的替代品。

## 2. Apple Silicon：显式设备适配与实测

[PyTorch MPS 官方文档](https://docs.pytorch.org/docs/stable/notes/mps.html)说明通过 MPS 设备在 Mac GPU 执行张量计算，以及可用性检查方式。它不保证每个模型、算子或训练路径都支持 MPS，也不保证总耗时优于 CPU。

本项目选择在设备适配层集中处理 `auto/mps/cpu/cuda`，同时检查 MPS 是否编译可用、运行可用，并分别验证推理、反向传播、缓存脚本和评估脚本。对不支持的运算应有明确回退策略及日志。验收需记录峰值内存、冷/热运行、同步方式和输出一致性；合成张量通过不等于真实长录播通过。

## 3. 歌曲识别：指纹提供候选，歌词补充证据

[Chromaprint 官方仓库](https://github.com/acoustid/chromaprint)明确其主要面向近似相同音频的识别。由此推断：直播换人翻唱、升降调、不同编曲和清唱不能保证被原曲指纹命中，不能把指纹 API 的成功接入当成翻唱识曲已完成。

拟采用可插拔 `SongIdentifier`：先抽取代表性片段，向提供方查询，保留候选与证据，再结合听写得到的歌词关键词缩小范围。用户最终确认歌曲名与原唱；“未知”必须是合法结果。后续若采用商业识曲服务，应使用其官方能力说明、配额、数据处理与接口条款重新评估，本文不预设某个服务对翻唱的识别保证。

指纹匹配的是录音证据，歌词匹配的是文本证据，两者分数不直接等价。候选置信度应标注提供方，不能将不同 API 的原始分值直接相加后显示为校准概率。

## 4. 歌词获取、转录、对齐分别处理

[Whisper 官方仓库](https://github.com/openai/whisper)提供多语言语音识别等能力，可作为本地转录候选。唱歌包含拖音、伴奏和改词，转录输出仍需人工检查；不能把模型生成文本视为歌词版权库或可靠歌曲署名。

[Montreal Forced Aligner 官方仓库](https://github.com/MontrealCorpusTools/Montreal-Forced-Aligner)提供基于已知转录的强制对齐工具。强制对齐处理“这段文字对应何时”，不同于歌词源检索，也不同于没有文本时的听写。其针对本项目中文演唱的可用性仍待实测，本文未选定生产对齐器。

首版导入本地 LRC，让用户直接检查时间轴。后续歌词供应方、ASR 与对齐器各自保存来源和版本；有行级时间就做行级字幕，有真实词级时间才做逐词推进。错误文本会影响对齐，逐字效果不能由等分行时长伪造。

## 5. 字幕与媒体导出：FFmpeg + ASS

[FFmpeg subtitles 滤镜官方说明](https://ffmpeg.org/ffmpeg-filters.html#subtitles-1)说明字幕烧录与 libass 依赖。选择生成 ASS 以承载字体、布局与高亮，再通过 FFmpeg 渲染 MP4，并独立导出 MP3。

当前媒体适配器默认选用 imageio-ffmpeg 随包 FFmpeg（已选构建含 libass），可配置外部 FFmpeg；FFprobe 仍需单独安装。需通过运行时探测检查实际构建是否具备所需编码器、滤镜和字体支持。关键帧流复制切片与字幕烧录的编码路径不同；精确切点、兼容性、速度需针对所选路径测试。左右 KTV 布局本身不等于词级对齐；没有逐词时间时保留行级表现。

## 6. 浏览器与桌面共用服务

[Tauri 官方 sidecar 文档](https://v2.tauri.app/develop/sidecar/)说明外部二进制的打包和执行机制，可作为桌面启动本地服务的候选方案。本项目据此规划 Tauri 壳、React 共享控制台与本地 FastAPI 服务；Python/PyTorch、FFmpeg、检查点的具体分发方式尚需验证。

桌面壳必须承担进程生命周期、退出清理和端口冲突处理。签名、公证、arm64 依赖、字体与模型下载均是发行验证项；仅能在开发机打开窗口不构成可安装发行版。先验证 Apple Silicon 完整链路，再用同一领域协议适配其他系统。

## 下一轮调研需要回答的问题

5. macOS 独立安装包如何合法、可更新地分发 Python、模型、FFmpeg 和字体？
