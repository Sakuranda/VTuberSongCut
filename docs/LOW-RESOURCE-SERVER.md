# 低配服务器与多人使用

本次增加录播姬接入、默认320p预览、CPU分块检测和受限任务队列。服务器训练默认关闭；在本地训练兼容模型，再由管理员导入服务器。实际负载仍需在目标 Linux 主机测试，本机合成测试不能作为并发人数或长录播速度承诺。

## 启动与录制

```sh
./scripts/deploy.sh --recorder
# 需要域名时
./scripts/deploy.sh --recorder --domain songs.example.com
```

部署脚本会生成并保留独立录制凭据、启动固定版本录播姬并设置回调；在“录播库”添加 B 站房间号。需要 Cookie 获取画质时，在录播姬自身管理页面配置。详情见 [录制接入](RECORDING.md)。没有启用录播服务时，手动上传仍可使用。

Docker 默认只在主机回环地址绑定拾歌端口；域名入口由 Caddy 提供 HTTPS。录播姬管理端口不对公网开放。每份数据目录只运行一个 API 服务；额外实例会在恢复任务前被工作目录锁拒绝，不能通过增加 workers 提高并发。

## 预览与导出

- 每个不可变源文件生成一份共享省流预览：最高320p、最高24fps，H.264目标300 kbps／峰值400 kbps，AAC64 kbps。小视频不放大，音频文件直接播放。
- 首次打开默认低清；未准备好时显示准备状态，不偷偷回退到高码率原片。既有项目通过后台队列逐步补齐预览，失败后手动重试。
- 高清按需准备，最高1080p/30fps；兼容的原MP4可直接播放，兼容FLV可复制码流封装，不兼容时才转码。切换清晰度保持播放位置，不改变片段或歌词时间。
- 修改边界、歌曲信息和字幕只修改草稿。精确导出从原始素材渲染所选片段；快速导出复制H.264/AAC码流，切点受关键帧影响，可能包含边界以外的内容，不支持烧录字幕、改变分辨率或帧率。
- 同一个任务的重复请求合并；不同用户的相同导出参数复用已生成媒体，但仍分别保存各自的项目快照和访问权限。
- 编辑API不缓存；视频和下载经权限校验后采用60秒私有缓存及`Vary: Authorization`。播放/下载连接与总发送速率受限。当前使用Caddy反代和应用受控文件流，未额外接入CDN或对象存储。

## 独立账户和剪辑

默认服务器账号仍是管理员。需要多人独立使用时，复制并编辑样例：

```sh
cp deploy/accounts.example.json server-accounts.json
chmod 600 server-accounts.json
# 将示例密码替换为每人不同的强密码（至少16字符）
./scripts/deploy.sh --recorder
```

脚本发现 `server-accounts.json` 后读取并作为服务端配置传入容器环境，不需要放宽宿主机文件的0600权限。容器管理员可像查看其他环境配置一样查看它，请勿公开容器完整配置。该文件被 Git 忽略，修改账户后重启应用生效。源代码模式设置 `SONGCUT_USERS_FILE` 为可读取的绝对路径，或使用 `SONGCUT_USERS_JSON`（二选一）；文件必须保留至少一个管理员，原 `.env.server` 管理员默认仍有效。

| 角色 | 能力 |
| --- | --- |
| admin | 管理录制、模型、缓存及所有项目 |
| editor | 浏览共享录播，创建自己的剪辑副本，上传、检测和导出自己的项目 |
| viewer | 浏览共享录播，按配额准备低清/高清预览；不能编辑、上传、检测或导出 |

普通账户无法读取别人的私人草稿、原始媒体或导出产物；录播姬导入项目是共享素材，编辑者先创建个人副本。副本引用同一原片和预览，不再复制完整录播。草稿仍使用版本校验避免多个页面静默覆盖。会话令牌绑定当前账户，管理操作只在服务端授权。

## 默认资源预算

这些是可调整的保护值，不代表同配置机器都能达到相同吞吐。

| 配置 | 默认 |
| --- | --- |
| `SONGCUT_LOW_RESOURCE` | Docker/服务器为1，本地为0 |
| `SONGCUT_CPU_THREADS` | 低配1；本地2，可设1–32 |
| `SONGCUT_QUEUE_LIMIT` | 20个排队/运行任务合计 |
| `SONGCUT_USER_QUEUE_LIMIT` | 每账户2个排队/运行任务 |
| `SONGCUT_TASK_TIMEOUT_SECONDS` | 7200秒 |
| `SONGCUT_UPLOAD_CONNECTIONS` | 2个并行上传 |
| `SONGCUT_UPLOAD_LIMIT_MB` | 单次16384 MiB，包含分块上传前置检查 |
| `SONGCUT_DISK_RESERVE_MB` | 服务器1024 MiB，本地128 MiB |
| `SONGCUT_EXPORT_MAX_SECONDS` | 低配1800秒；本地86400秒 |
| `SONGCUT_MEDIA_CONNECTIONS` | 12个媒体/下载请求，不等于12个人 |
| `SONGCUT_HD_CONNECTIONS` | 2个高清/视频下载请求 |
| `SONGCUT_MEDIA_MBPS` | 服务器媒体总预算10 Mbps；0表示关闭速率限制 |
| `SONGCUT_CPUS` / `SONGCUT_MEMORY` | Docker应用1.5核配额／2 GiB上限 |
| `SONGCUT_RECORDER_CPUS` / `SONGCUT_RECORDER_MEMORY` | 录制器0.5核配额／512 MiB上限 |

低配导出最高1080p、30fps、H.264。训练API明确拒绝执行，界面保留模型导入。FFmpeg解码、滤镜、编码及推理线程受限。录制独立运行，检测/转码/导出共用一个计算执行位，按用户轮换排队；后台预览保留交互任务的队列余量。

任务参数与输入版本持久化。正常服务关闭会终止自身计算进程组，结构化任务在下次启动重新处理；原片或模型已经变化则失败提示，不套用旧结果。早期版本只有内存闭包的任务仍标为中断，需重新提交。

单次上传在multipart写入过程中检查总量和磁盘；磁盘不足保留原素材并拒绝新计算。录制盘有独立水位保护和明确暂停状态，见录制说明。由内核强杀、主机断电造成的遗留进程恢复仍需部署环境以容器/systemd清理整组进程；不承诺所有外部终止场景都能续算到精确步骤。

## CPU检测

CPU路径流式解码16kHz单声道音频，只保留当前窗口和低帧率概率序列。CRNN默认120秒窗口、30秒重叠；TCN因上下文较长保留600秒窗口。可设 `SONGCUT_INFER_CHUNK_SECONDS` 与 `SONGCUT_INFER_OVERLAP_SECONDS`；缩小窗口必须用真实录播复核检测效果，不能默认认为精度完全一致。

模型代码、特征配置和完整检查点需要匹配。检测只处理源音频，不把320p低码率预览用于模型输入。结果按源文件身份、模型、推理版本/参数缓存复用。它仍然只检测目标主播演唱区间；歌名、原唱和歌词的参考库识别不在本轮实现范围内。

测试已覆盖真实CPU子进程、原推理同窗口的数值对照、取消和异常清理。目标Linux还应检查真实长录播的耗时、峰值内存、录制时丢帧情况和多人播放响应；低于预算的主机要降低任务规模或在本地处理重任务，不能靠增加队列获得更多算力。
