# 运行缓存维护

2026-10-20：增加页面底部“缓存管理”，提供分类容量、重新检查、一键清理、成功及部分失败反馈。

## 范围

| 文件 | 清理条件 |
| --- | --- |
| `training/jobs/<id>/features/*.npy` | 训练任务已结束 |
| `jobs/<id>/*.probs.npy` | 检测任务已结束 |
| `jobs/<id>/*.mp4` | 预览任务已结束，且没有项目引用该文件 |
| `training/previews/<sample-id>.mp4` | 样本已移出数据集，且无该样本正在处理的预览任务 |
| 训练预览的 `.pending` 及 FFmpeg 隐藏中间 MP4 | 文件中的任务 ID 对应已结束的训练预览任务 |

终态为 succeeded / failed / cancelled / interrupted。扫描使用数据库记录的 ID 和固定目录，不接受客户端文件路径；不跟随符号链接或目录联接。所有被项目或训练数据引用的源文件受到保护。未知文件不处理。

训练检查点、模型、原始录播、导出目录、日志、检测片段 JSON、快照及数据库保留。清理不会改项目版本或未保存草稿。旧预览被清理时移除该任务对应的下载项；已经不存在的下载返回 404。

## 调度与接口

- `GET /api/cache`：返回可清理文件数、字节数、分类与自动保留天数。
- `POST /api/cache/clean`：重新扫描后清理可回收缓存，返回实际删除数、字节数和失败数。沿用服务器认证与会话令牌校验。
- 自动回收：服务 lifespan 启动时及此后每小时，按文件最后修改时间回收超过 7 天的可清理文件。关闭服务时结束维护线程；维护失败记录日志，之后重试。
- 手动清理没有年龄限制，正在处理的任务与已引用的文件始终跳过。Windows 文件占用导致的删除失败不会阻止其他文件清理。
- 媒体和 API 使用 no-store；首页 no-cache。静态资源及已有浏览器磁盘缓存由浏览器管理，皮肤偏好不清空。
