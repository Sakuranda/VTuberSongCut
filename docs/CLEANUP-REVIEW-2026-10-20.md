# 2026-10-20 构建文件清理记录

## 原因

本机发现源码环境中的一份 `libtorch_cpu.dylib`，以及打包暂存、Tauri debug/release 资源中的副本。旧 debug/release 资源中，PyInstaller 的根目录兼容链接还被复制成了实体文件。打包暂存中的同名根目录项目前是 28 字节符号链接，不应按 386 MB 再算一份。不能通过单独删除运行库来清理，否则可能破坏动态库加载或已签名应用。

## 本轮处理

- 添加默认预览的跨平台 `scripts/clean.py`，固定路径白名单、进程占用检查，保护源码环境和用户数据；拒绝经过符号链接或目录联接的清理目标。
- 本机执行默认清理，移除旧 debug/release 的完整 `backend` 资源副本及 PyInstaller 中间输入，文件大小合计 2595.7 MiB。保留编译缓存避免重新编译耗时。
- 保留源码运行库和打包暂存的运行库；可选参数可以在不再需要打包暂存时清理整个暂存后端。
- 成功冻结后端后自动移除本次构建中间文件，失败保留现场；`--keep-build-work` 可保留调试资料。
- 没有重打安装包、修改已发行二进制或改动录播／模型／导出数据。

## 验证

完整后端回归：155 项通过、1 项可选测试跳过；其中新增清理测试 11 项全部通过。清理后实际导入 PyTorch 成功。

清理测试覆盖白名单、用户数据／安装包保护、默认预览、嵌套符号链接、链接父目录拒绝、桌面／构建运行时拒绝、进程枚举失败时拒绝、可选暂存清理、重复清理。清理后本机仍保留 `.venv` 中的 PyTorch 和打包暂存库；默认再次预览为 0 MiB。

此变更不尝试在安装包内重写或合并动态库，也不自动删除崩溃后归属不明的用户媒体。Windows 的进程检查使用 PowerShell/CIM，链接测试在系统不允许创建链接时跳过；本轮实际清理环境为 macOS。
