# 路线图与验收标准

下列内容是交付目标，不是已完成功能清单。当前运行方式、已执行测试及限制以根 README 为准。优先交付 macOS Apple Silicon 本地完整流程，再扩展平台与外部服务。

## P0：可复现本地编辑与导出

- 从干净环境按文档启动浏览器控制台和 Python 服务，依赖缺失时给出可操作错误。
- 上传真实视频和纯音频各一份，正确探测长度；刷新后工程及手动片段仍可读取。
- 编辑起止点、歌曲名、原唱和演唱者；非法范围被拒绝，两个客户端同时编辑会报告版本冲突。
- 用固定阿梓检查点完成检测；记录检查点来源、哈希、设备、输入长度及耗时。模型失败必须显示失败原因。
- 导入包含中文、重复时间与偏移的 LRC；预览、单行/双行/左右 KTV 和最终导出时间一致。无词级时间不显示虚假逐字精度。
- MP4 和 MP3 可播放，片段长度符合约定误差；烧录字幕无越界，中文字体正确。验证每片段视频/音频输出开关、H.264/HEVC、分辨率、帧率、质量/目标码率及音频码率可保存并反映到最终媒体；异步导出保留提交时设置。
- 逐帧微调采用探测所得源帧率，覆盖 23.976/29.97/59.94 等非整数帧率；未知帧率显示回退行为。
- 使用真实授权阿梓录播做盲测：按录播划分训练/验证/测试，记录漏切、误切、合并拆分与边界误差；报告不得混用合成输入测试结果。

## P1：Apple Silicon 稳定性与桌面发行

- CPU/MPS 的训练、推理、评估、特征缓存均有可复现命令与结果；合成输入只证明路径可运行。
- 长录播压力测试覆盖内存、磁盘不足、模型异常、工作器退出；重启后运行中任务显示可理解的中断状态。
- 工程编辑与后台检测并发时不丢失新编辑；任务记录输入 revision，处理冲突有测试。
- 引入可恢复任务调度、取消、重试和幂等产物写入；用主动杀进程测试验证，不能仅检查数据库有记录。
- Tauri 壳可启动/停止本地服务，避免重复实例与孤儿进程；浏览器与桌面共用同一业务契约。
- 在未配置开发环境的 arm64 Mac 上安装、运行、导出和卸载；模型获取、FFmpeg/libass、字体、签名/公证与版本更新均明确处理后，才标注为桌面可发行。

## P2：歌曲候选与可信歌词

- 实现 `SongIdentifier`，将音频指纹与歌词片段证据合并为候选；可显示“未知”，允许人工选择/改写。
- 用同一首歌的原版、直播翻唱、升降调、清唱、聊天干扰测试，分别报告准确率和覆盖率；不以原曲音频指纹命中率替代翻唱识别能力。
- 歌词来源、本地转录和强制对齐分开记录来源与版本；检索失败不静默改为猜测歌词。
- 逐词对齐在中文拖音、换气、重复句、改词及间奏上人工校验；不可靠时退回行级字幕。
- 原唱与直播演唱者贯穿工程、界面、导出命名与发布元数据，不相互覆盖。

## P3：发布与内容辅助

- B 站投稿、音乐网站发布分别实现 `Publisher`；先生成可审阅的标题、封面、标签和文件清单，再执行用户明确触发的发布。
- 凭据不进入工程文件、仓库或日志；凭据失效可恢复，重复点击或网络重试不会重复发布。
- AI 封面与标题通过独立端口提供候选；保存生成来源，支持人工修改。
- 对各平台使用获准接入方式，分别验收草稿、上传进度、失败恢复与远端结果核对。

## P4：其他系统与多模型

- Windows 与 Linux 各自通过干净环境安装、媒体探测、模型推理、字幕与导出测试后宣布支持；CUDA 是单独验证项。
- 增加其他主播模型配置，不把阿梓模型推广为通用歌手检测器；为每个模型独立记录适用范围和验证集。
- 有真实需求后再评估多人协作、远程服务和多工作器；迁移前保持工程 schema 可版本化、适配器可替换。

## 发布前证据

每次发布保留系统/芯片、Python/PyTorch/FFmpeg 版本、上游 commit、补丁版本、模型哈希、测试素材说明及结果。第三方代码、检查点、字体和素材的授权分别核实；代码仓库许可证不能代替模型与内容授权。
