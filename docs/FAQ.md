# 拾歌常见问题

<a id="models"></a>
## 选哪个模型？

模型决定拾歌要找“谁在唱歌”。阿梓模型只适用于阿梓，不能把它当作所有主播通用的唱歌检测器。处理自己的主播时，先进入独立训练工作区，训练完成后回到切歌工作区选择新模型。项目中选择的模型与设备会保存；未选择模型时不能直接检测。

模型选择旁的“？”可悬停查看简短说明，并点击进入训练与常见问题。主界面以切歌操作为主；训练素材和训练任务放在独立工作区。

### 预配置、导入和训练有什么区别？

- **预配置**：已准备好的官方阿梓模型，可用于相应主播或参考操作流程。
- **导入**：把别人或自己已经训练好的兼容模型加入模型库。上传文件不会再次训练。
- **训练**：用真实录播与人工标注学习目标主播的演唱特征，成功后产生一个新模型。

`.pt` / `.pth` 只是文件扩展名。拾歌接受兼容 AutoSlicer 格式的检测模型，不能使用 RVC 音色转换模型。导入失败时查看错误说明；详细格式见 [模型说明](MODELS.md)。

### 模型会识别歌名，或把声音换成主播吗？

它找的是“目标主播正在唱歌”的时间范围，不负责歌名、原唱或歌词识别，也不会改变声音。歌曲信息与歌词需使用工作台当前提供的填写和导入功能。

### 运行设备怎么选？

不确定时可先选自动。Apple Silicon Mac 在环境支持时可选择 MPS，也可选择 CPU；其他平台可用设备以界面检测结果为准。训练和检测速度取决于素材长度、模型与机器；设备不可用时会报错。需要排查环境时再看 [详细说明](MODELS.md)。

<a id="training"></a>
## 怎么训练自己的主播？

在拾歌的训练工作区创建数据集、填写目标演唱者，上传训练和验证素材，标出演唱区间并完整复核，再开始训练。训练完成后回到切歌工作区选择新模型，检测新的录播。原项目没有训练界面；拾歌负责界面和数据准备，底层调用原项目训练程序。

训练自己的主播需要相应的真实录播和人工标注。合成素材只能验证程序流程，不能用于证明主播模型的实际检测质量。

### 上传显示 100%，为什么还在检查素材？

上传百分比表示文件传输进度。文件发送完成后，拾歌还会检查时长和内容，确认可用后才显示“素材已导入”。检查期间无需重复上传；上传或检查失败的原因会显示在上传区域，可重新选择文件。

### FLV 一定要生成兼容预览吗？

**用于训练不需要先转换。** 拾歌可以直接读取 FLV 原素材；但网页和桌面内置播放器通常不能直接播放 FLV，因此在界面中观看、标注时需要生成兼容预览。能直接播放的素材无需转换。

兼容预览是另存的可播放副本，不会替换原文件，训练仍读取原素材。生成时显示实际处理进度，文件完成后才显示 100%；失败原因会显示在进度条下方。成功的预览会保留，刷新页面后可以继续使用，无需重复生成。

### 标注录播时有哪些快捷键？

视频可播放后，点击播放器或时间轴：**空格 / K** 播放或暂停，**← / →** 前后移动 1 秒，**Shift + ← / →** 前后移动 10 秒。跳转时会暂停，方便定位。

按 **I** 把当前播放位置设为标注开始，按 **O** 设为结束，再按 **A** 添加这段标注，使用当前选择的演唱者类别。添加后仍需复核并保存；无效时间或重叠区间会显示错误。输入框、下拉框和按钮获得焦点时保留原有键盘操作，切回切歌工作区后训练快捷键不生效。

### 训练集和验证集是什么？为什么分开？

训练集是给模型学习的素材；验证集用于检查它对没有参与学习的素材表现如何。两组至少各有一个独立素材，并且都要含目标演唱和非目标演唱。

尽量按整场录播分组，例如几场用于学习，另一场用于验证。把同一场剪成两份会保留相同的录音环境和内容，容易让分数看起来更好。程序会拦截完全相同的重复文件，但无法自动发现转码或裁剪后的同场录播（仅改名的相同文件仍会被拦截）。

### 哪些部分该标成目标演唱？

只把目标主播本人唱歌的部分标成“目标演唱”。播放原唱、播放其他歌手、其他人演唱应标成“其他人演唱”。聊天、读弹幕、纯伴奏等不属于目标演唱。

同一首歌里目标主播暂停、改放原唱，再继续唱时，应按实际声音分段标注；不要把整首歌的时间范围都标成目标演唱。片段不能重叠。遇到目标与他人同时演唱等不确定场景，先用能明确判断的素材建立第一版模型，保证标注一致。

### 为什么要确认“已完整复核”？

确认表示你已经检查了整个素材：标为目标的地方用于学习目标演唱，**未标注的所有地方也会作为非目标演唱**。这不是“剩下的地方不参与训练”。如果只标了前几首歌就确认，后面的目标演唱会被错误地当作负例。

先检查有没有漏歌、错误身份和时间错位，再确认。修改标注后需要重新确认。若长录播暂时无法完整复核，先准备能够完整检查的较短素材，并保持训练和验证来自不同录播。

### 只准备主播唱歌的声音够吗？

不够。模型还要知道哪些声音不应切出来。训练和验证两组都要同时包含目标演唱与非目标演唱；聊天、伴奏、原唱播放和其他歌手的演唱能帮助暴露不同类型的误切。只含目标演唱的素材组无法开始训练。

### 分数很高，是否说明训练成功了？

训练完成说明产生了可加载的模型；验证结果说明它在这批验证素材和标注上的表现。高分不保证其他录播效果，也不保证歌曲边界准确。

精确率低通常表示误判较多，召回率低通常表示漏掉较多，F1 综合两者。当前展示的帧级结果衡量短时间单位的判断，不能直接理解成“切对了多少首歌”。还应选择一场既不在训练集也不在验证集中的录播，检查漏歌、原唱被误切、聊天被误切和歌曲起止点。

### 训练失败或中断怎么办？

先看任务日志和错误原因。常见原因是未确认完整标注、某一组缺少目标或非目标内容、设备不可用、内存不足或素材变化。修正后重新发起；内存不足时可减小批量大小。服务重启会把运行中的任务标记为中断，当前需要重新发起，不能自动接着上次进度训练。

### 原项目在哪里？想直接用命令怎么做？

运行安装脚本后，原项目位于拾歌仓库下的 `upstream/AutoSlicer-v2/`。它是独立 Git 仓库，仅加入 Apple Silicon 兼容补丁。拾歌的训练界面、通用数据准备与模型库均保存在拾歌主仓库。共享环境、模型位置、本地推理及高级训练命令见 [模型与原项目说明](MODELS.md)。

## 如何清理网页使用产生的缓存？

点击页面底部的 **缓存管理**，可以查看分类大小并清理。不必删除整个数据目录或清空浏览器的所有站点数据。

可清理内容包括已结束训练的特征缓存、检测概率中间文件、不再被项目使用的兼容预览、已结束任务遗留的预览临时文件。服务启动后及运行期间每小时自动检查，回收其中超过 7 天的文件；手动清理没有等待天数限制。

原始录播、模型、训练检查点、标注、导出成品、日志和当前使用的预览会保留。正在运行或排队的任务跳过；执行清理时会重新检查引用状态，不使用打开面板时的旧结果。少数被系统占用的文件会保留并提示稍后重试。

媒体与接口响应使用 `Cache-Control: no-store`，首页每次验证版本。图片、脚本和样式仍由浏览器管理；皮肤偏好保留。此机制不会追溯删除浏览器以前缓存的数据，也不会清空其他站点。正常上传失败与预览异常的临时文件会在原操作结束时清理；崩溃后归属不明的上传素材不会按文件名或年龄猜测删除。

这是运行缓存清理，与[开发环境构建清理](DEVELOPMENT.md#构建文件清理)分开。
