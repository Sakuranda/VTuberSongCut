# 2026-10-18 外观与可靠性验收

本轮在独立测试数据中使用合成视频进行操作检查。已有用户项目与录播未参与修改；首次查看真实工作目录时只读取已有内容。

## 发现与修复

| 体验问题 | 调整 |
| --- | --- |
| 蓝白色固定，无法按个人偏好调整 | 猫娘／简洁皮肤，四套配色及浅色／深色／跟随系统 |
| 皮肤可能分散剪辑注意力 | 插画集中在欢迎页和外观面板；编辑期间只保留小头像 |
| 深色表单、提示、时间轴颜色不统一 | 使用语义颜色变量，覆盖切歌、训练、模型、上传、任务与错误状态 |
| 辅助文案过小，窄屏覆盖样式更小 | 提高小字尺寸，检查小屏和短窗口布局 |
| 外观面板底部操作可能超出短窗口 | 面板头尾固定在可见区，选项区域独立滚动 |
| 服务重启后，旧页面的保存和上传会话过期 | 只对后端明确在执行前拒绝的过期会话刷新并重试一次 |
| 单个媒体工具检查失败导致项目也无法加载 | 项目与工具检查独立进行，失败提供就地重试 |
| 训练项目首次读取失败后缺少重试入口 | 增加重新读取项目，加载期间禁用重复操作 |
| 迟到的项目列表可能覆盖新建项目或未保存标注 | 保留当前选择与草稿，忽略已离开页面的旧请求 |
| 默认端口被其他软件占用导致桌面版启动失败 | 另选本机端口，最多三次；用进程、端口就绪信号及健康检查确认自己的后端 |

会话恢复不会自动重放普通权限错误、断网或无法确认结果的操作，避免重复上传或提交。桌面启动不会结束占用端口的其他程序，退出只清理自身启动的服务。

## 验证记录

- 前端：47 项测试通过，TypeScript 与 Vite 生产构建成功。
- 后端：144 项通过、1 项可选测试跳过；有一条已有的依赖弃用提示。
- 桌面启动：本机 Rust 8 项通过；1 项子进程测试入口标记 ignored，由其他测试显式启动，并非未验证的功能场景。
- 真实 Python 子进程：随机端口启动、就绪文件中的进程和端口核对、会话获取、自身关闭清理；占用端口时不写就绪信号，原监听器保持运行。
- 界面：内置浏览器 1280×720，Chrome 390×844；外观面板无横向溢出，短窗口关闭／完成可见，小屏训练表单不溢出。
- 界面：更改皮肤与配色后，歌曲名称草稿和未保存状态保持；刷新后偏好保留；简洁模式不显示角色。
- 界面：编辑草稿后真实重启测试后端，不刷新页面直接保存成功。
- 界面：首次工具检查返回 503 时仍可读取并编辑项目；点重试后保留草稿。首次训练列表读取失败，点重新读取项目后恢复。
- 自动测试：并发会话刷新、取消上传、重复拒绝、普通权限失败；训练列表迟到时保留新项目与未保存标注。
- 配色测试：八组明暗／配色的主要文字对比度至少 4.5:1、控件边界至少 3:1。

## 范围与边界

本轮在评审分支保存独立提交，没有合并到主分支，也没有重新发布桌面安装包。桌面端口修复需要新版原生壳与新版 Python 后端一起打包；浏览器验收和本机 Rust 测试不等同于 Windows／Linux 安装包的实机验收。

本轮改善界面与失败恢复，不宣称提高演唱模型准确率。实际模型训练质量、不同显卡驱动和长时间真实录播负载仍需专项验证。
